# Bitcoin BTC/USD Analytics Pipeline

This repository contains a complete Jupyter Notebook pipeline for analyzing Bitcoin (BTC/USD) 1-minute OHLCV data. It processes the raw historical data into cleaned minute data, daily features, statistical analyses, machine-learning evaluations, time-series forecasts, anomaly/regime analysis, and an executive dashboard.

## Dataset

Download the Kaggle Bitcoin Historical Data dataset:

<https://www.kaggle.com/datasets/mczielinski/bitcoin-historical-data>

The pipeline expects the raw file to be named `btcusd_1-min_data.csv`.

## Project goals

This project is designed to turn high-frequency Bitcoin market data into a reproducible research workflow. It focuses on:

- Data-quality validation for missing intervals, duplicates, invalid prices, and zero-volume periods.
- Multi-timeframe OHLCV aggregation from 1-minute bars to daily, monthly, and yearly data.
- Market behavior analysis across returns, volatility, drawdowns, volume, calendar effects, and Bitcoin halving cycles.
- Statistical testing of return behavior, stationarity, autocorrelation, and volatility clustering.
- Detection of unusual market days and clustering of daily observations into market regimes.
- Out-of-sample next-day direction classification and time-series forecast benchmarking.

## Setup

Create and activate a virtual environment, then install the dependencies:

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Start Jupyter or open the notebook in VS Code:

```bash
jupyter notebook Bitcoin_Analytics_Full_Pipeline.ipynb
```

The notebook currently uses the Windows paths below. Create the output directory before execution, or update the paths in the notebook to match your machine:

```text
C:\Users\Admin\Downloads\archive\
|-- btcusd_1-min_data.csv
`-- out\
```

The raw CSV is large and the first stage may require substantial memory, disk space, and processing time.

## Running the pipeline

Run the notebook cells from top to bottom. The stages are:

1. Load and audit the raw minute data.
2. Build daily, monthly, and yearly datasets and engineer features.
3. Produce exploratory data analysis charts and summaries.
4. Run statistical tests and GARCH volatility analysis.
5. Detect anomalies and segment market regimes.
6. Evaluate walk-forward machine-learning models.
7. Decompose the time series and benchmark forecasts.
8. Create the correlation heatmap and executive dashboard.

## Analytical methods

The pipeline combines descriptive analysis with predictive and statistical methods:

- Rolling returns and annualized volatility over 7-, 30-, and 90-day windows.
- Historical maximum drawdown, moving-average ratios, RSI-style momentum, volume changes, and calendar features.
- ADF/KPSS stationarity checks, Ljung-Box/autocorrelation analysis, distribution tests, and GARCH(1,1) volatility modeling.
- Robust modified z-scores and Isolation Forest for anomaly detection.
- KMeans clustering with standardized market features for regime segmentation.
- Logistic Regression, Random Forest, and HistGradientBoosting classifiers evaluated with expanding-window walk-forward validation.
- Naive, autoregressive, and ARIMA forecasting benchmarks for daily returns, plus monthly decomposition.

Machine-learning results are intended as out-of-sample research benchmarks. They are not a trading strategy and do not include transaction costs, slippage, position sizing, or execution constraints.

## Input data columns

The source file should contain the standard Kaggle columns:

`Timestamp`, `Open`, `High`, `Low`, `Close`, and `Volume`

`Timestamp` is interpreted as Unix time in seconds and converted to a pandas datetime index. Price and volume columns are loaded as memory-efficient floating-point values where appropriate.

## Reproducibility and limitations

- Run cells in order because later stages read Parquet files generated by earlier stages.
- The notebook is currently configured with absolute Windows paths; portability requires replacing those paths with local or relative paths.
- Results depend on the exact source-data version, date range, missing-minute behavior, and installed package versions.
- Historical patterns and model metrics do not guarantee future performance.
- This project is for educational and analytical use only and is not financial advice.
